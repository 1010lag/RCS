# Реализация RCS

## Локальная рабочая версия

Интерфейсы админа и бариста подключены к API с сохраняемой серверной PostgreSQL/PGlite. График, роли, расчёты, биржа, персональные уведомления, аудит и основные административные формы реализованы. Это версия для локального знакомства и проверки; подготовка production-релиза ещё не завершена.

Fastify и SSE заменяют предложенные NestJS/WebSocket. SSE передаёт общую ревизию без личных данных; клиент перечитывает только разрешённые ему API. Дневные итоги вычисляются по сменам и корректировкам, без дублирующей таблицы payroll_daily. Факт считается по завершённому расписанию, без учёта присутствия.

Транзакции сериализуются: в PGlite очередью, в PostgreSQL advisory lock. Забор дополнительно блокирует строки, GiST-ограничение запрещает пересечения. Для небольшой команды это выбор простоты и согласованности. Один процесс API владеет локальной PGlite и worker доставки.

## Перед использованием командой

- Подключить Firebase; проверить push, разрешения и ссылки на настоящих Android/iPhone.
- Развернуть по HTTPS, создать настоящего админа, проверить резервное копирование и восстановление PostgreSQL.
- Выполнить проверки адаптера на обычной PostgreSQL в CI; локально проверяется PGlite, Docker недоступен.
- Проверить доступность, контраст и удобство на устройствах команды.
- Добавить экран массового назначения, предварительный просмотр повторения недели и отдельное копирование смены. Сейчас повтор недели атомарный: конфликт откатывает всю операцию.
- Добавить сброс забытого пароля администратором и политику очистки старых сессий/событий/уведомлений.
- Перед несколькими API-инстансами добавить конкурентное резервирование push-доставок; сейчас worker рассчитан на одного отправителя.
- При развитии схемы перейти от повторяемого начального SQL к нумерованным миграциям существующих баз.

Удаление сотрудника переносит профиль в архив и сразу убирает его смены из общего графика. Текущие и будущие незавершённые смены автоматически отменяются, открытые объявления закрываются, сессии и устройства push отзываются. История завершённых смен и начислений сохраняется. Откат обмена не разрешает повторное выставление той же смены. Ставка нового владельца показывается до подтверждения и сверяется по версиям.

Секреты, база, пароли аккаунтов, снимки экранов и отчёты исключены из Git.

## Удаление и данные для входа

В «Команда» и «Типы смен» добавлены кнопки удаления с подтверждением. Записи перемещаются в отдельные архивы; восстановление доступно через редактирование. `PATCH /employees/:id` с `active:false` в одной транзакции отзывает доступ, отменяет текущие и будущие незавершённые смены, закрывает объявления и записывает причины в аудит. Общий календарь исключает назначения неактивных сотрудников, а прошедшие смены и начисления остаются в истории и отчётах. Удаление типа отключает новые назначения и его биржу, сохраняя существующие смены и их оплату.

Администратор может менять телефон и задавать новый пароль через `PATCH /employees/:id`; пароль необязателен, хранится только в виде Argon2id-хеша и не попадает в аудит. При смене собственного пароля текущая сессия сохраняется, остальные отзываются. При сбросе пароля другого сотрудника его сессии отзываются, а при следующем входе требуется задать личный пароль.

## Аватарки и проверка

`PUT /me/avatar` принимает только собственную фотографию либо `null` для удаления. Клиент обрезает изображение до квадрата, сервер проверяет формат и повторно кодирует его в WebP 256×256 без метаданных. Действуют ограничения размера и числа пикселей; SVG и повреждённые файлы отклоняются. Изображение хранится в базе и передаётся через `/team` и проекцию смены, поэтому видно на других устройствах и в офлайн-снимках.

Для версии 0.1.8 локально прошли 48 серверных/модульных проверок, 12 браузерных сценариев и проверки на физическом Redmi. Сценарии удаления и смены паролей на телефоне выполнялись в отдельной базе в памяти. Подробности подключения и артефактов — в `docs/ANDROID.md`.

## Индивидуальная почасовая ставка

В карточке бариста в разделе «Команда» выделено действие «Изменить ставку в час». API: `PATCH /api/employees/:id/hourly-rate`, только для админа. Принимает `rate`, `version`, `reason`, `apply_to_future`.

Новая ставка применяется к новым почасовым сменам. По выбору админа обновляются уже назначенные почасовые смены, которые ещё не начались. Прошедшие, фиксированные и смены с ручной ставкой не пересчитываются. Обновление пользователя, будущих ставок, закрытие связанных открытых объявлений, аудит и уведомление выполняются одной транзакцией. Устаревшая версия профиля возвращает конфликт.
