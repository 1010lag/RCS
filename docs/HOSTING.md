# Публичный сервер: Render + Supabase

Опубликованная версия: **https://rcs-team-1010lag.onrender.com**. Первоначальные данные перенесены 1 ноября 2026 года из локальной резервной копии. Вход, календарь, сотрудники, типы смен, расчёты, SSE и готовность Android push проверены через публичный HTTPS-адрес. Удалённые GitHub Actions и 98 локальных серверных тестов прошли.

Приложение запускается целиком: React, API, SSE и worker обслуживает один Node.js-процесс, данные сохраняются в отдельной PostgreSQL. Компьютер в кофейне после переноса не нужен. HTTPS предоставляет хостинг.

## Бесплатные тарифы

- Render Web Service **Free**, Node.js 24, регион Frankfurt. HTTPS и публичный адрес включены. После 15 минут без входящих обращений сервис засыпает; следующее открытие запускает его примерно за минуту. Пока сервис спит, фоновые напоминания не выполняются. Это ограничение выбранного бесплатного тарифа.
- Supabase **Free**, PostgreSQL, европейский регион поблизости от Frankfurt: 500 MB базы на проект, 5 GB исходящего трафика, до двух активных проектов. Проект может приостановиться после недели неактивности. Уведомления и состояние тарифа нужно проверять в панели Supabase.
- Не подключайте платный тариф или карту для этого развёртывания. При исчерпании бесплатных квот сервис может приостановиться.

Официальные условия: [Render Free](https://render.com/docs/free), [Supabase Free](https://supabase.com/pricing), [подключение Render к Supabase](https://render.com/articles/how-to-connect-a-render-service-to-supabase-postgres).

## Развёртывание

1. Создайте проект Supabase Free. В Connect выберите **Session pooler**, порт **5432**: он доступен по IPv4 и сохраняет сессию соединения. Бесплатный прямой адрес Supabase использует IPv6, недоступный для исходящих соединений Render. Строку подключения с TLS храните как секрет. Приложение использует PostgreSQL напрямую, Supabase Auth и браузерный Data API ему не нужны.
2. Перенесите данные по инструкции ниже **до запуска публичного сервера**, чтобы worker не создал записи в пустой базе назначения.
3. В Render создайте Blueprint по `render.yaml` из репозитория `https://github.com/1010lag/RCS`. Он выбирает Free, Node.js 24, сборку `npm ci --include=dev && npm run build`, запуск `npm run start:hosted`, health check `/api/health`.
4. В `DATABASE_URL` передайте Session pooler URI Supabase с параметрами `sslmode=verify-full&sslrootcert=server/certs/supabase-root-2021.crt`. Официальный открытый CA-сертификат Supabase включён в репозиторий, проверка сертификата и имени сервера сохранена. `APP_ORIGIN` берётся из `RENDER_EXTERNAL_URL`; для собственного домена укажите полный HTTPS origin без пути. `HOST=0.0.0.0`, `NODE_ENV=production` уже заданы в Blueprint.
5. В действующей установке Android push использует секретный файл Render `firebase-service-account.json`, переменные `GOOGLE_APPLICATION_CREDENTIALS=/etc/secrets/firebase-service-account.json` и `FIREBASE_PROJECT_ID=rcs-pro`. Для других хостингов поддерживается альтернативная секретная переменная `FIREBASE_SERVICE_ACCOUNT_JSON` с полным JSON. Не добавляйте закрытый JSON в Git или публичные файлы сайта.
6. Если нужен маршрут скачивания APK, задайте `APK_DOWNLOAD_URL` — публичный HTTPS-адрес существующего APK. Он используется только при отсутствии `.data/apk/RCS.apk` на сервере.
7. Откройте публичный адрес, проверьте `/api/health`, вход, календарь, ставки, аватарки, сохранение изменений и обновление второго клиента. Проверьте повторное открытие после перезапуска.

Аватарки уже хранятся в базе как data URL и переживают перезапуск. `start:hosted` останавливается с ошибкой, если отсутствует PostgreSQL или корректный HTTPS origin: случайно запустить пустую временную PGlite на хостинге не получится.

Схема включает RLS для всех таблиц RCS без разрешающих браузерных политик и отзывает права `anon`/`authenticated`. Поэтому сгенерированный Supabase Data API не раскрывает телефоны, хеши паролей, сессии и расчёты. Сервер подключается владельцем таблиц и применяет существующие проверки ролей RCS. Если Data API не используется другими приложениями проекта, его также можно отключить в панели Supabase.

В режиме `start:hosted` worker запускается к ближайшему сроку задачи, а успешное изменение API будит его сразу. Когда задач нет, служебная проверка выполняется раз в час. Это сокращает лишние запросы, но не отменяет сон самого Render Free.

## Перенос существующей базы

Остановите локальный API, чтобы копия была согласованной. Скопируйте `.data/database` в новую папку резервной копии внутри `.data/backups/`. Исходную базу не удаляйте. Экспорт читает отдельную **не используемую сервером копию**:

```sh
npm run db:transfer -- export .data/backups/cloud-export.json .data/backups/offline-database
```

Экспорт содержит приватные данные и хеши паролей. Храните его вне Git и публичного каталога. После задания `DATABASE_URL` новой PostgreSQL в окружении:

```sh
npm run db:transfer -- import .data/backups/cloud-export.json
```

Импорт создаёт схему и проверяет, что **все** таблицы назначения пустые. Записи вставляются одной транзакцией, с проверкой схемы и количества строк. При ошибке вставки откатываются; существующая непустая база не перезаписывается. SQL даты, время, числовая точность, большие идентификаторы событий, пароли и аватарки сохраняются. После успешного переноса не используйте локальную и облачную базы для параллельного редактирования: это отдельные копии.

## Android и PWA

В Android смените адрес сервера на публичный HTTPS-адрес и войдите заново. Приложение уже умеет менять сервер без переустановки. Включите уведомления на устройстве заново после входа. На iPhone и в браузере открывайте тот же HTTPS-адрес; PWA можно установить через меню браузера. Для браузерного push по-прежнему отдельно нужны Web-конфигурация Firebase и VAPID.

## Периодическая проверка сервера

Она обращается к серверу в минуты `00`, `13`, `26`, `39`, `52` каждого часа: максимальный промежуток — 13 минут, на границе часа — 8 минут. Тестовый запрос из cron-job.org вернул `200 OK` и `{"ok":true}`. Управление: https://console.cron-job.org/jobs/8769542.

Задача поддерживает входящий трафик между обращениями пользователей. Перезапуски платформы и месячные квоты бесплатного Render остаются в силе.
