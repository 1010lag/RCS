# RCS для Android

Android-приложение собирается в устанавливаемый APK с пакетом `by.rcs.app`, названием RCS и собственной иконкой. Интерфейс включён в APK, соединение с API выполняется через нативный HTTP-модуль Capacitor. Это отдельное Android-приложение, а не установка PWA через меню браузера.

## Установка первой сборки

В текущей локальной конфигурации APK доступен с телефона в одной домашней сети:

http://192.168.1.7:3001/download/rcs.apk

Скачать файл `RCS.apk`, открыть его и подтвердить установку. Если Android запросит разрешение установки из Chrome/файлового менеджера, разрешить установку для выбранного источника. Сборка рассчитана на Android 7.0/API 24 и новее.

Исходный APK находится в `.data/apk/RCS.apk`. Это подписанная отладочная сборка для локальной проверки, без публикации в Google Play. Подпись и метаданные APK проверяются инструментами Android SDK. Первое подключение ADB нужно подтвердить на телефоне; отдельные прошивки также запрашивают подтверждение установки.

## Обновление через подключённый телефон

Для Android 11+ доступно сопряжение по Wi-Fi через «Для разработчиков → Беспроводная отладка → Сопряжение с помощью кода». Компьютер и телефон должны находиться в одной сети. Команды `adb pair IP:PAIR_PORT` и затем `adb connect IP:CONNECT_PORT` используют разные порты, показанные на телефоне. Код вводится при сопряжении и не сохраняется в проекте.

После авторизации устройства:

```powershell
npm run android:install
# Пересобрать перед установкой:
npm run android:install -- -Build
# Выбрать конкретный телефон, если подключено несколько:
npm run android:install -- -Serial IP:CONNECT_PORT
# Установить и проверить интерфейс на подключённом телефоне:
npm run android:install -- -Serial IP:CONNECT_PORT -VerifyUI
```

Скрипт устанавливает APK с `-r`, сохраняя данные приложения, запускает RCS, проверяет процесс и активное приложение, затем сохраняет снимок экрана и журнал процесса в `.data/qa/phone`. Эти файлы исключены из Git. Это проверка установки и запуска; сценарии интерфейса проверяются отдельно. Если телефон отключился от Wi-Fi, ADB может потребовать повторного подключения.

Флаг `-VerifyUI` подключает Playwright к WebView именно установленного RCS через временный локальный ADB-порт. На телефоне должен быть выполнен вход, RCS должен оставаться открытым, а экран — разблокированным. Проверяются отступ верхней панели, отсутствие горизонтальной прокрутки, кнопка уведомлений, меню, график, профиль и карточка ближайшей смены (если она есть). Смены и начисления не изменяются. Результат сохраняется в `.data/qa/phone/ui-check.json`, проброс порта удаляется после проверки. Системные касания ADB на Redmi могут требовать «Отладку по USB (настройки безопасности)»; проверки внутри WebView используют отладчик приложения.

Проверено 1 ноября 2026 года на физическом Redmi 15 (25062RN2DY), Android 16: RCS 0.1.11 / versionCode 12 установлен с сохранением данных. Прошли проверки навигации, отступов и тем. На отдельной базе в памяти проверены имя и фамилия, аватарка во всех видах графика, непрерывные недели месяца с подписанными соседними датами и светлым фоном граничных ячеек, смена данных для входа с текущим паролем, увольнение с оплатой текущей части смены и сохранением архивной истории, отмена будущих смен и удаление типа без почасовой ставки. После проверки восстановлены исходный сервер и аккаунт телефона; рабочие данные этими сценариями не изменялись. Фактическая область WebView — 384×832 CSS px; верхняя панель начинается после системного отступа 46 px. Результаты и снимки находятся локально в `.data/qa/phone`.

Темы доступны в «Профиль → Тема оформления» (в веб-панели — «Настройки»). По умолчанию используется светлая тема. Выбор хранится локально на устройстве, работает без сети и сохраняется при обновлении APK; в браузере синхронизируется между вкладками. Android меняет цвет системных значков вместе с темой.

Имя, фамилия и аватарка изменяются в профиле и сохраняются на общем сервере; они видны в календаре команде. Администратор меняет собственные телефон и пароль кнопкой «Изменить телефон и пароль», а данные бариста — через «Команда → Редактировать профиль», подтверждая текущим паролем. Данные для входа другого администратора защищены от сброса. Смена пароля отзывает старые сессии и push-подписки.

## Общий сервер

Первый адрес сервера: `http://192.168.1.7:3001`. Он включён в локальную сборку. При недоступном сервере приложение показывает экран подключения; адрес можно изменить. Также он меняется в профиле через кнопку «Сервер».

Для первой проверки компьютер с сервером должен быть включён, а телефон подключён к той же домашней сети. График, сотрудники, ставки и биржа остаются в общей серверной базе. Android-клиент использует те же права и CSRF-защиту, что веб-панель. Сессии обрабатываются нативным cookie-хранилищем. Изменения в Android проверяются каждые две секунды через авторизованный маршрут ревизии; браузерная версия продолжает использовать SSE.

Публичный сервер должен использовать HTTPS. После его развёртывания адрес можно сменить в приложении без переустановки. При смене сервера очищаются локальная история сессии, персональный кэш и cookies, чтобы данные разных серверов не смешивались.

В Windows для проверки открыт только входящий TCP-порт 3001 из `192.168.1.0/24`, правило `RCS-Phone-LAN-3001`. Запуск для домашней сети: `npm run dev:lan` или `npm run start:lan`. Обычный `npm run dev` оставляет API на loopback.

## Повторная сборка

Нужны Node.js 24+, JDK 21, Android SDK 36 и Build Tools. Скрипт находит инструменты, установленные локально в пользовательской `.codex/.tmp`, или использует заданные `JAVA_HOME`/`ANDROID_HOME`.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-android.ps1 -ApiUrl http://192.168.1.7:3001
```

Скрипт собирает интерфейс, выполняет `cap sync android`, запускает Gradle `assembleDebug` и копирует готовый APK в `.data/apk/RCS.apk`. Конфигурация, исходники Android, wrapper и иконки включены в репозиторий; локальные SDK, ключи и результаты сборки исключены из Git. Workflow `Android APK` подготовлен для сборки артефакта в GitHub Actions после отправки исходников.

## Android push

В APK включён нативный модуль `@capacitor/push-notifications`. Для его активации нужен Firebase-проект, зарегистрированное Android-приложение с пакетом `by.rcs.app`, файл `android/app/google-services.json` и настроенный сервер отправки. Файл конфигурации исключён из Git. После его добавления APK нужно пересобрать: скрипт автоматически включит регистрацию Android push. Пока Firebase не настроен, приложение работает с графиком и центром уведомлений, а системные push отключены.

Сервер хранит тип устройства и отправляет Android notification payload через FCM, чтобы уведомление могло отображаться системой, когда приложение закрыто. На Android 13+ требуется разрешение пользователя. [Документация Capacitor Push](https://capacitorjs.com/docs/apis/push-notifications).
