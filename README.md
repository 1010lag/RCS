# RCS

Система графика смен для команды одной кофейни: мобильный PWA для бариста и веб-интерфейс администратора.

Язык — русский, валюта — BYN, бизнес-время — `Europe/Minsk`.

## Быстрый запуск

Нужен Node.js 24 LTS или новее. Локально проверено на Node.js 26.13.0 / Windows.

```sh
npm ci
npm run demo
npm run dev
```

Открыть http://localhost:5173. Демо-команда создаётся только в пустой базе. Случайный пароль и телефоны — в `.data/demo-access.txt`, исключённом из Git. Повторный `npm run demo` существующие данные не перезаписывает.

На текущем Windows-компьютере Node установлен локально, без изменения системного PATH. Для повторного запуска:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\dev.ps1
```

Для настоящей команды вместо демо выполнить `npm run admin` и создать первого администратора интерактивно. Сотрудников добавляет админ в интерфейсе; при первом входе они меняют временный пароль. Общего административного пароля в исходниках нет.

## Реализовано

- Вход по телефону и паролю, Argon2id, HttpOnly-сессии, CSRF и ограничение попыток входа.
- Серверные роли и приватность: бариста видит общий график и только свои начисления; сотрудники, ставки и аудит доступны админу.
- Типы смен, индивидуальные ставки, создание/редактирование/отмена смен. Почасовая ставка задаётся сотруднику, в типе остаётся только фиксированная оплата за смену.
- Календарь день/неделя/месяц, фильтр собственных смен и поиск сотрудника. Месяц показывает непрерывные недели; соседние месяцы отличаются светлым фоном и подписью даты. На телефоне все семь дней помещаются по ширине, по умолчанию открыт день.
- Удаление сотрудников и типов смен с подтверждением и архивом. Текущая смена заканчивается в минуту увольнения, будущие отменяются; завершённые остаются в графике и расчётах.
- Имя и фамилию можно изменить в собственном профиле. Администратор меняет свой телефон/пароль и сбрасывает доступ бариста с подтверждением текущим паролем. Данные для входа другого админа защищены от сброса.
- При смене пароля все прежние сессии и push-устройства отзываются; текущему клиенту выдаются новые cookie и CSRF.
- Загрузка аватарки в профиле, хранение на сервере и отображение в графике день/неделя/месяц. Светлая и тёмная темы с сохранением выбора на устройстве.
- План и факт раздельно, часы без вычета обеда, почасовая/фиксированная оплата BYN, корректировки с причиной.
- В «Команда» у каждого бариста есть «Изменить ставку в час»: отдельная сумма Br/час и выбор пересчёта будущих назначений. Прошлые, фиксированные и вручную переопределённые ставки сохраняются; изменение с причиной записывается в журнал.
- Биржа: выставление, отзыв, личный расчёт до подтверждения, атомарный забор, идемпотентность и откат админом.
- Персональные корректировки не переходят новому владельцу: передача и откат смены с корректировками запрещены. Старые перенесённые корректировки учитываются для исходного получателя.
- Повторная публикация не дублирует уведомления; есть минутный интервал и лимит 5 публикаций за 15 минут. Автор и владелец не получают уведомление о собственной публикации.
- Запрет ночных и пересекающихся смен в БД. Граница биржи — начало смены или 19:00 её дня по Минску, что раньше.
- Realtime через авторизованные SSE; история уведомлений и персональные настройки.
- Worker напоминаний, закрытие объявлений, завершение смен по расписанию, сохраняемая очередь push.
- PWA, кэш оболочки и персональный IndexedDB-кэш для чтения без сети. Изменения требуют подключения, выход очищает персональный кэш.

## База и собранное приложение

Без `DATABASE_URL` работает серверная PostgreSQL в WASM (PGlite), сохраняющая данные в `.data/database`. Отдельная СУБД для знакомства не нужна. Одновременно открывать эту папку двумя процессами нельзя: перед `npm run admin` или `npm run demo` остановите API.

Для обычной PostgreSQL задайте `DATABASE_URL` в `.env` по `.env.example`. Начальная схема `server/schema.sql` применяется при старте, нужны права на создание `btree_gist`. Локальные данные PGlite автоматически в другую базу не переносятся.

```sh
npm run build
npm start
```

Собранные интерфейс и API доступны на http://localhost:3001. Офлайн-PWA проверяется на собранной версии: Vite/HMR для офлайн-кэширования не предназначены.

Для публикации: `NODE_ENV=production`, `APP_ORIGIN=https://ваш-домен`, PostgreSQL и HTTPS reverse proxy. Production-cookie требует HTTPS. Подготовлены Dockerfile и compose.yaml; Docker здесь отсутствует, контейнерный запуск не проверен. `POSTGRES_PASSWORD` задаётся извне; специальные символы должны корректно кодироваться в URL соединения.

В `TRUSTED_PROXIES` перечислите только IP/CIDR собственных reverse proxy (например, `127.0.0.1,::1`). По умолчанию `X-Forwarded-For` игнорируется. Ограничения входа по аккаунту и IP сохраняются в БД после перезапуска. SSE ограничен тремя соединениями на пользователя и общей проверкой сессий раз в секунду; очередь БД, параллельные запросы и тяжёлые операции также ограничены. [Подробности](docs/IMPLEMENTATION.md).

## Push на телефон

Центр уведомлений работает без внешних сервисов. Для реальной доставки задайте `GOOGLE_APPLICATION_CREDENTIALS` (путь к сервисному аккаунту вне репозитория), `FIREBASE_WEB_CONFIG` (публичный JSON), `FIREBASE_VAPID_KEY` и `APP_ORIGIN` по HTTPS. Затем включите push в профиле и разрешите их в браузере.

Для пошаговой настройки есть `npm run push:setup`, а в профиле — состояние подписки, «Проверить push» и отключение текущего устройства. Админ дополнительно видит состояние конфигурации и очереди. Закрытые ключи не выводятся и не передаются клиенту. [Инструкция подключения](docs/PUSH_SETUP.md).

Worker повторяет временные ошибки и отбрасывает устаревшие напоминания. Начальное развёртывание рассчитано на один процесс API/worker. Учётная запись Firebase сейчас ещё не подключена, реальная доставка на Android/iPhone не проверена. Для телефона нужен доступный HTTPS-адрес RCS с работающим API; localhost подходит только для проверки на самом компьютере.

## Проверки

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Серверные тесты используют отдельную PGlite в памяти. Браузерные запускают собственный сервер на 3181 с отдельной базой и не меняют пользовательские данные.

Для проверки обычной PostgreSQL задайте `TEST_DATABASE_URL` с именем отдельной базы, оканчивающимся на `_test`. Тесты очищают её таблицы. GitHub Actions настроен на оба режима; удалённый CI пока не запускался.

## Структура

`web/` — React/TypeScript; `server/` — Fastify API, PostgreSQL, worker; `shared/` — типы; `tests/` — серверные и браузерные проверки. [Реализация и оставшаяся работа](docs/IMPLEMENTATION.md).

Вместо предложенных в спецификации NestJS/WebSocket выбраны Fastify и SSE: команды идут по HTTP, сервер сообщает клиентам об изменениях. PostgreSQL и серверные бизнес-правила сохранены.

Репозиторий: https://github.com/1010lag/RCS. `origin` настроен; отправка изменений выполняется через Git CLI с доступом владельца.
